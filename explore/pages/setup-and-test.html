Software only: the sim

Anyone / works now

This runs the real controller against a MuJoCo SO-101 that picks scripted grasps. It tests the controller, timing, reach and region limits, and the spoken lines. It does not test the Isaac policy.

.venv/bin/python -m controller --sim-arm --port 8031 --sim-port 8032
# watch:   http://localhost:8032/web/viewer.html   (Live mode)
# camera:  http://localhost:8032/stream
# run a pass, resetting the tray between runs:
curl -XPOST localhost:8032/scene/reset; curl -XPOST localhost:8031/reset
.venv/bin/python -m controller.smoke --url http://localhost:8031 --return

You should see every item "coming", each put-back "back in its slot", the count "Everything's on the tray", run 1: CLEAN, and about 5.2 s from request to hand.

Gotchas found today
  1. Don't run python -m vision --fake while using --sim-arm. The sim already feeds its own vision, and the fake hand fights it ("Hand open, please. / No hand").
  2. Port 8000 is in use on this laptop by another process, so use --port.
  3. After a scalpel handoff the sim scalpel sits at the safe spot. Call POST /scene/reset before the next run (new today).

Which item is which: OCR or not

Brandon / decision

Recommendation: no OCR. Surgical instruments carry no text a camera can read from overhead. The only markings are tiny laser-etched catalog codes, a few mm tall. Dental tools and bench tools are the same.

What the code already does is better. vision/tray.py asks Perceptron's detector for the item by name ("scalpel", "hemostat", "mayo scissors"), then checks the detection against that item's slot box. That gives two signals that should agree:

SignalStrengthWeakness
Slot position (the tray layout)Always available, needs no modelWrong if someone puts an item back in the wrong slot
Perceptron detect by name (in code)Sees the actual shape; catches a swapped slotAbout a second per call; needs the key; hemostat and scissors look alike
Printed ArUco tag in each slot (optional)Instant, offline, about 100% reliable; OpenCV already reads themShows the slot is empty, not which item is in it

If detect confuses the hemostat and the scissors in testing, add ArUco tags before trying OCR: a tag that becomes visible means "slot empty". Printed text labels would work too, but a tag does the same job with far less effort. Real ORs identify instruments by tray position and count sheets, which is also what Scrub does.

Camera to arm

Brandon + Anish

Calibrate at hand height, not on the table. The homography only holds for one height. Fit it on the table and the palm, about 18 cm up, lands 31 to 57 mm off (sim rehearsal). Fit it at hand height and the error is 1 to 8 mm.

  1. Tape 6 to 8 printed markers on a flat board about 18 cm above the table, spread over the handoff area. Or record the gripper tip at that height.
  2. Measure each marker's x (forward) and y (left) in meters from the arm's shoulder pan axis.
  3. Open prototype 42 with ?vision=http://localhost:8001. Click each marker, type its x and y, and set the board height. Download pairs.json. It scales the pixels to the camera's 1280x720 itself.
  4. python -m vision.calibrate --pairs pairs.json writes vision/calibration.json and prints the max error. It should be under 2 cm (page to tool tested: 1.03 cm on mock clicks).
  5. Check it: hold a palm still over a tape mark and compare the Hand target with the tape.
