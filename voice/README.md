# voice

Owner: Caiden. Tasks C3, C4, C7 in `team/LEFT.md`.

TypeScript on Node 20, port 3000. Code in `src/` (`server.ts` is the entry), `scripts/say.ts` (one fake caller turn), `scripts/test.ts` (`npm test`). Photon number, then the ElevenLabs agent over SIP (photon.codes/docs/beta/cookbooks/voice/elevenlabs), then what it hears comes here. "stop" goes straight to `POST /stop`. Everything else goes to Gemini (structured output: one action, one item id from the current setting), then `POST /command`. Speaks the `say` line of each event from `WS /events`. Texts the end-of-case summary on Photon.

Done when: "grab me the kelly" on the call becomes `handover hemostat` at the controller and Scrub answers out loud.

## How a call reaches us

caller -> Photon number -> Photon Voice profile (SIP, TLS) -> ElevenLabs agent (speech to text, text to speech) -> its LLM is "Custom LLM" = our `POST /v1/chat/completions` through a public tunnel. Each caller turn prints `[heard] ...`. The reply streams back as OpenAI `chat.completion.chunk` SSE lines (`data: {...}\n\n`, then `data: [DONE]\n\n`) and the agent speaks them. The first chunk goes out before the controller answers; the reply stays open up to `VOICE_HOLD_S` (14 s: longer than the 10 s hand wait plus a set-down) to speak follow-up event lines ("Scalpel down."). A line that lands with no turn open (a dashboard or smoke handover) is spoken at the start of the next turn only if it is under 10 s old, and only the last 2.

- We only act when the last message is the caller's. ElevenLabs also asks for a reply after silence; that gets an empty reply instead of a repeated command.
- The system prompt line `Caller: {{system__caller_id}}` gives us the caller's number for the summary text (`[case] caller +1...`). If that line never prints, Photon isn't passing caller id over SIP: set `PHOTON_SUMMARY_TO` in `.env`.
- Optional: `VOICE_LLM_SECRET=<anything>` in `.env` makes the endpoint require `Authorization: Bearer <it>`. ElevenLabs sends its `OPENAI_API_KEY` secret that way, so give that secret the same value. A mismatch prints `[server] 401`. With it set, `POST /heard` and `POST /summary` also need it when they come through the tunnel (a forwarding header, or not loopback); plain local curl still works.
- Any other path prints `[server] 404 POST /...`: the Custom LLM URL is wrong.
- One call at a time. The system prompt line `Conversation: {{system__conversation_id}}` names the call (also read from `elevenlabs_extra_body.conversation_id`, or a `conv_...` `user_id`). While one call has spoken in the last `VOICE_BUSY_S` (45 s), a turn from another call gets "Scrub is busy with another call. Try again in a minute." and nothing moves, its caller id doesn't take the end-of-case text, and the log prints `[busy] <id> said "..." while <id> is on`. Exception, safety first: "stop" from any call still goes to `POST /stop` (`[busy] ... : stopping anyway`). The active call frees after `VOICE_BUSY_S` of caller silence (a silence ping doesn't count). No id (the line unfilled, a simulated call, `/heard`, `/talk`, `npm run say`) is never busy and never claims Scrub. No caller allowlist: any number works.

## Run and test

- `npm run dev` (port 3000). `CONTROLLER_URL` and `VOICE_PORT` from the shell override `.env`, so a test copy can run beside the real one: `CONTROLLER_URL=http://localhost:8071 VOICE_PORT=3071 npm run dev`. Keys only come from `.env`. For a test copy, use `VOICE_NO_KEYS=1`: it ignores `.env`, so the copy never calls Gemini or Photon and never texts: `VOICE_NO_KEYS=1 CONTROLLER_URL=http://localhost:8071 VOICE_PORT=3071 npm run dev` (it logs `[texts] off`). A key set to empty in the shell (`PHOTON_API_KEY= ...`) also blanks just that key.
- `curl localhost:3000/health`: `{"ok":true,"keys":{"gemini":..,"photon":..,"llm_secret":..},"controller":true,"controller_url":"http://localhost:8000","turns":3,"gemini_ms":412,"gemini_p50_ms":380,"timing":{"turns":3,"heard_to_command_p50_ms":395,"gemini_p50_ms":380,"controller_p50_ms":12,"first_line_p50_ms":640,"last":{...}},"active_call":false}`. Booleans only for keys, never values. `gemini_ms` is the last Gemini parse time and `gemini_p50_ms` the median of the last 50 (null before any). GET answers send `access-control-allow-origin: *`. When an event carries `skill_source: "taught"`, the `[say]` log line ends `, taught skill)` and the end-of-case summary adds a line such as `3 handovers: 2 by the model, 1 by a taught skill`. The spoken reply is unchanged.
- Per-turn timings: each caller turn (call, `/heard`, `/talk`) logs `[timing] heard->command 395ms, gemini 380ms, controller 12ms, first line 640ms` when its reply closes. All from the request arriving: heard->command is when `POST /command` (or `/stop`) is sent, gemini the parse time (`local` when the alias match ran, `-` when nothing parsed: tray check, end of case, a tray switch), controller that POST's round trip, first line when the first spoken line went into the reply (`-`: said nothing). `/health` `timing` has the medians of the last 50 turns (a turn without that step doesn't count toward it) and `last`, the newest turn's numbers; `npm run say` prints both after its reply.
- No phone: open http://localhost:3000/talk on the voice laptop. Hold the button (or the space bar), speak, let go: the browser's speech recognition (Chrome, Safari) sends the words to `POST /heard` like a caller turn and speaks Scrub's lines back; a text box works without a microphone. Speech recognition needs localhost or https, so from another machine on the LAN only the text box works, and with `VOICE_LLM_SECRET` set it gets a 401 (the page says so and takes the secret for that tab). `npm run talk` is the same in the terminal (type a line, get Scrub's reply).
- No call needed: `npm run say -- "grab me the kelly"` sends what ElevenLabs sends and prints the streamed reply with timings. It sends no caller id, so it never changes where the live server's end-of-case text goes; `SAY_CALLER=+1...` acts as that caller. `VOICE_URL=https://<tunnel> npm run say -- "stop"` does it through the tunnel. `curl -XPOST localhost:3000/heard -d '{"text":"grab me the kelly"}'` returns the lines as JSON.
- Robot-model errors: the controller's `error` events (optional `code` 401, 409 or 503, and a `say` line) are spoken like any event line, during a turn and in the hold window, and end the hold. The end-of-case summary does not count them as failed requests.
- `npm test`: offline. Its fake controller uses ports 3020-3023 and its voice server 3024-3027; in-process code points at 3029, where nothing listens, so it never reaches the live controller on 8000. Alias match, case summary counts, caller id and last-message rules, and the real server against a fake controller: SSE chunk shape, `[DONE]`, "stop" hits only `POST /stop` (no `/setting`, no Gemini, no `/command`), "check the tray" hits only `GET /tray_check`, `/health`, and passes made while the events socket was down still counted after the reconnect. `VOICE_NO_KEYS=1` (set by `scripts/test-env.ts`, imported first by the test) ignores `.env`, so it never calls Gemini or Photon.
- Gemini: checked Oct 17 live, kelly, mayo, "knife please", "what's out" and "stop" all map right. The first Gemini call after start can pass the 1.5 s timeout and fall back to the alias match.
- Nothing waits forever: the `WS /events` socket pings every 5 s and reconnects after a missed pong (a controller that went away without closing). After a reconnect it reads `GET /events/recent?n=500` from the newest event it saw before the drop and adds the missed events to the case summary (`[events] backfill checked N events since the drop`), deduped by event (`t`, `type`, `command_id`, `item`). Missed lines are never spoken. A drop longer than the controller's last 500 events can still undercount. A Photon connect or send fails after 15 s, a text reply after 30 s, and the summary uses the template if Gemini takes over 8 s. "stop" retries `POST /stop` once.
- The setting is cached for 30 s and dropped when an event shows a different setting, so a turn doesn't wait on `GET /setting` before Gemini.
- Clinic words (X6): "call the hemostat a clamp", "clamp means the hemostat", "when I say clamp I mean the hemostat" are caught by a local pattern (`parseAlias` in `src/parse.ts`) before Gemini, on the call and by text (texts also have a Gemini `alias` kind). The item side has to name an item on the tray. They go to the controller's `POST /alias` (saved in `settings/<id>.local.json`), Scrub says its `say`, and the cached setting is dropped so the next turn hears the new word. The Command action enum is unchanged.
- End-of-case summary: the count comes first, from the controller's own `out` list. A no-pull or no-hand set-down is listed as "set at the safe spot", not as a pass; a pick that worked on the retry is not a failed request.

## Texts

### Which one?

Items may optionally have `group` and `variant` strings. A shared word asks before posting movement, for example "Which screwdriver: flathead or Phillips?" Say the variant, full name, first/second, either/any/you pick, or cancel/never mind. "You pick" prefers real measured success rates from `/stats`, then the nearest candidate by distance/position (image-bottom is closer), then stable list order when neither is available. Fake/sim rates and the controller-memory fallback are not treated as real measurements. Stop never waits for this lookup. Gemini may return a parser-only `clarify` intent or request a yes/no confirmation; neither adds a controller action, and uncertainty never moves before yes.

Each question has a real 15-second timer, not just an expiry check on the next utterance. It clears pending state, logs `clarify_answer` with `answer: "timeout"`, and says "That question timed out. I'll wait for you to ask again." Duplicate HTTP/websocket copies share the original deadline. Answer, cancel, stop, supersession and case/setting changes clear the timer; cancellation is logged too. Text timeout notices use the originating space's sender proactively. Only streaming phone replies stay open for the question's remaining 15 seconds (the first question chunk is immediate); interruption closes the speech stream but retains the pending answer. `/heard`, nonstreaming replies and text questions return promptly. A closed phone reply cannot receive unsolicited speech: its timeout notice uses the same context's existing queue and is replayed only within the existing 10-second stale-line window on the next turn.

The same flow runs on calls and Photon text threads. Questions are scoped to `Conversation:` (caller id as fallback), a Photon space id (sender as fallback), or `/heard`'s optional `context` string. Text replies never answer a call's question. `POST /command` may return `clarify: {say,item,candidates,question_id?,confirm?}` or emit a `clarify` event with the originating `command_id`. `confirm: true` requires yes/no even for one candidate. Backend-issued question ids accompany the resolved command; local telemetry question ids do not. Candidates accept `{item?,id?,label?,group?,variant?,side?,slot?,instance?}` plus optional distance/position metadata; left/right/closest answers become `Command.instance`, never an invented item. Physical returns clear matching instance history, not every recipient with that item. Voice-generated questions and answers are sent best-effort to `POST /clarify` for telemetry. An HTTP-only refusal such as "already out" is spoken too, with duplicates suppressed. Incoming texted stops bypass the ordinary text-work queue, including a hanging photo or summary.

"Another", "same again" and "one more" use the last instrument handed to this conversation, not someone else's request. "Put it back" / "take it back" return that same instrument, including its selected instance. With no history, Scrub asks for a name instead of letting a global last-out fallback choose. "The other one" uses the unselected option from this conversation's last answered question (asks again if more than one option remains). A stop, case close, or tray change clears this context. Explicit named returns keep their item id.

`npm test` includes `scripts/test-which-one.ts`: deterministic ambiguity and Gemini validation, every choice/cancel phrase, fake-clock expiry, independent call/text contexts, by-sight command routing, telemetry, and real `/heard` and `/v1/chat/completions` routes against a fake controller. No hardware or API keys.

Text the Photon number (same iMessage thread as the end-of-case summary). The listener only starts when `PHOTON_PROJECT_ID` and `PHOTON_API_KEY` are in `.env`; otherwise the server logs `[texts] off`. Gemini reads the text (structured output, the current setting's item ids plus `surgical`/`bench`); with no key or a Gemini error it falls back to a local match.

Judge mode: when `GET /state` has `judge: true`, the controller only takes handover, count, stop and got_it. Voice then never posts `/setting`, `/alias` or `/restock` (tray switches, clinic words, restocks, by call or text) and answers `In judge mode I can hand you an instrument, read the count, or stop.` On the call the flag comes from `GET /state`, cached `VOICE_JUDGE_TTL_MS` (3000) and only asked on those paths, so stop and handover never wait on it. A 403 from `POST /setting` or `/alias` gets the same line.

Photos: text a photo of the count sheet (alone, or with "read the pack" or "what tray is this" to read a pack label or tray tag instead). Voice downloads it (Spectrum gives an `attachment` with `read()`, or a `group` of the caption and the attachment), turns HEIC into JPEG with macOS `sips`, and sends it to vision's `POST {VISION_URL}/read/<kind>?setting=<current>&today=<date>` (`VISION_URL`, default `http://localhost:8001`). The reply uses the controller's wording (`Sheet says 0 hemostats back, I count 1.`, `Expired: mayo scissors pack, 2026-09-30. Don't open it.`). Then voice posts vision's answer to the controller's `POST /read_result` (5 s), which sets `sheet` and `packs` like a camera read, switches trays from a tag photo when idle, emits the `read` event (`read.source: "photo"`) and words the reply. If the controller is down or errors, voice words it the same way here, a tray tag photo doesn't switch (it says `Text "switch to the bench tray" to change.`) and voice keeps the read for the end-of-case summary.

The end-of-case summary adds, after the count, `Count sheet matches.` or `Count sheet disagrees: hemostat (sheet 0, Scrub 1).` when a sheet was read this case (a `read` event, a `count` event's `sheet_mismatch`, a photo, or `GET /state` `sheet`), and `Expired pack: mayo scissors, 2026-09-30.` for each expired pack read.

Code in `src/texts.ts` and `src/reads.ts`; `npm test` runs it against a fake message stream and fake state, and a fake controller and vision on port 3093.

The end-of-case text (saying "end of case" on the call, or `POST /summary`) goes to the number that called (`Caller:` in the agent's system prompt) or else `PHOTON_SUMMARY_TO`, on that same thread. It names the case: count first, then `Scrub case: surgical, started 2:41 PM (23 min)`, the items used, what was passed, set down or failed, and the median request-to-hand time. Events are grouped by the controller's `case_id` (a new `case_id` starts a new case); without it, one case runs until "end of case".

Case link: with `SCRUB_PUBLIC_URL` set (non-secret, `.env` or shell, the ledger public page's URL), a second short text follows the summary: `Case replay: <SCRUB_PUBLIC_URL>/case.html?id=<case_id>` (Evan's replay page on the ledger public site). With `SCRUB_PUBLIC_URL` empty, `SCRUB_SERVER_IP` (the Vultr box) gives `http://<SCRUB_SERVER_IP>/case.html?id=...` (nginx on port 80 proxies to the ledger page, which serves `/case.html`). A "summary" text gets the same line after the summary in its reply. Neither set, or no `case_id` from the controller: nothing extra.

## Tunnel

ElevenLabs has to reach port 3000 from the internet. Every tunnel below gives a new URL each start (except ngrok's free static domain), so the agent's Custom LLM URL must follow it: `npm run agent -- <url>` does that, and `run_all --real` runs it on every new URL.

- `npm run tunnel`: Pinggy over SSH on port 443, no account. Works on the venue Wi-Fi (Oct 17). Prints `https://<x>.run.pinggy-free.link`. Free tunnels end after 60 min: run it again and paste the new URL.
- `npm run tunnel:cf`: cloudflared quick tunnel (`voice/.bin/cloudflared`, gitignored; `--protocol http2`). Needs outbound port 7844: blocked on the venue Wi-Fi Oct 17, open Oct 18 at 1:30 AM (`nc -vz region1.v2.argotunnel.com 7844`). No 60 min limit. Get the binary: `curl -sL https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-darwin-arm64.tgz | tar xz -C voice/.bin` (brew needs the Xcode license). The default for `run_all --real` when the binary is there.
- `npm run tunnel:ngrok`: no authtoken on this Mac (Oct 18). Needs a free ngrok account once: `ngrok config add-authtoken <token>` (a human, from dashboard.ngrok.com). Claim the free static domain there and run `ngrok http --url=<name>.ngrok-free.app 3000` so the URL never changes.

Measured Oct 17, fake-arm controller, alias match (no Gemini): request to first streamed byte about 20 ms locally, 0.5 to 0.75 s through Pinggy on a fresh connection (about 0.27 s of that is the TLS handshake). The spoken line follows 0 to 60 ms later; "stop" is the fastest path (no setting fetch, no Gemini). Gemini adds up to the 1.5 s timeout.
